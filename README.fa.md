# xhttp-splitter

*[English](README.md)*

یک پروکسی محلی که **تونل `xhttp` (packet-up) در Xray** را زنده نگه می‌دارد، جایی که DPI
اتصال‌های TLS را بر اساس SNI محدود می‌کند. هر درخواست HTTP/1.1 از Xray روی اتصال TLS
تک‌مصرفِ خودش خارج می‌شود، پس هیچ اتصالی نه آپلودِ زیاد دارد و نه درخواست دوم حمل می‌کند تا
throttle شود.

```
xray (xhttp, security:none) → xhttp-splitter → هر درخواست یک اتصال TLS → edge IPs → server
```

مستقل از edge: فقط به یک SNI و IPها (یا رنج‌های CIDR) که آن را سرو می‌کنند نیاز دارد.

## مشکل

بعضی DPIها اجازه می‌دهند اتصال TLS باز شود، اما به‌محض اینکه کلاینت بیش از چند کیلوبایت
آپلود کند یا درخواست دومی روی آن بفرستد، blackhole می‌کنند؛ دانلودها محدود نمی‌شوند. Xray
اتصال‌های آپلودش را دوباره استفاده می‌کند، پس تونل `xhttp` در چند ثانیه گیر می‌کند — اول
آپلود. xhttp-splitter هر درخواست را روی اتصال تازه پخش می‌کند، یک warm pool نگه می‌دارد تا
هر POST یک رفت‌وبرگشت هزینه کند، درخواستِ گیرکرده را جای دیگر دوباره می‌فرستد، و ترافیک را
به‌سمت IPهایی که فعلاً کار می‌کنند هدایت می‌کند.

## سازگاری

transport مشخص، هر پروتکل داخلی. فقط `xhttp` در مود **packet-up** کار می‌کند: این مود آپلود
را به درخواست‌های مستقلِ شماره‌دار می‌شکند که سرور دوباره سرهم می‌کند — و همین اجازه می‌دهد هر
درخواست روی اتصال خودش سوار شود. تونل `ws`/`grpc`/`raw` یک جریان پیوستهٔ واحد است و قابل‌تقسیم
نیست.

| تنظیم Xray | |
|---|---|
| پروتکل داخلی VLESS / VMess / Trojan / Shadowsocks | ✅ به‌صورت HTTP/1.1 خام رله می‌شود |
| transport `xhttp`، مود `packet-up` (یا `auto`) | ✅ |
| session و seq در path، داده در body (پیش‌فرض‌ها) | ✅ |
| مسیر دانلود (`stream-down` GET) | ✅ |
| `ws` / `grpc` / `httpupgrade` / `raw` | ❌ تونل packet نیست |
| مود `stream-up` / `stream-one` | ❌ یک آپلودِ طولانیِ واحد |
| session/seq در query، header یا cookie | ❌ فقط path |

کانفیگ کلاینت: [`examples/xray-client.example.json`](examples/xray-client.example.json)
— `security: none` (اسپلیتر TLS را اضافه می‌کند)، outbound به اسپلیتر اشاره می‌کند.

## بیلد و اجرا

```
go build -o xhttp-splitter .        # باینری استاتیک، بدون وابستگی (Go 1.23+)

xhttp-splitter -sni cloudflare.com -ips 104.16.0.0/13,172.64.0.0/13
```

سپس outbound از نوع `xhttp` در Xray را به `127.0.0.1:10443` با `security: none` اشاره بده.
رنج‌های کوچک کامل باز و بزرگ‌ها نمونه‌برداری می‌شوند؛ بدون `-ips` خودِ SNI از DNS resolve
می‌شود. موقع استارت، استخر در پس‌زمینه probe و به IPهای تمیز محدود می‌شود، و وقتی تعداد
تمیزها کم شود دوباره probe می‌شود.

| Flag | متغیر محیطی | پیش‌فرض | |
|---|---|---|---|
| `-sni` | `XHTTP_SNI` | اجباری | دامنهٔ edge (SNI و Host پیش‌فرض) |
| `-ips` | `XHTTP_IPS` | DNS `-sni` | IP / رنج CIDRهای سرودهندهٔ SNI |
| `-ech` | `XHTTP_ECH` | خاموش | مخفی‌کردن SNI: `auto`، `dns:HOST:PORT`، یک URL، یا base64 |
| `-listen` | `XHTTP_LISTEN` | `127.0.0.1:10443` | آدرس listen محلی |
| `-window` | | `12` | seqهای در پرواز؛ زیر `scMaxBufferedPosts` سرور |
| `-copies` | | `2` | حداکثر تلاش هم‌زمان برای هر درخواست |
| `-post-timeout` | | `20s` | تسلیم‌شدن روی یک درخواست (سشن را می‌بندد) |

بقیه با `-h`.

## پیدا کردن IPهای تمیز

توصیه: کافی است یک رنج به `-ips` بدهی و بگذاری خودِ اسپلیتر مدیریت کند — رنج را probe می‌کند،
IPهای تمیز را نگه می‌دارد و با سوختنشان دوباره probe می‌کند، بدون کار دستی. از `scan` فقط وقتی
استفاده کن که بخواهی یک ست ثابت پیدا و پین کنی: از رنج‌ها IPهای تصادفی را تست می‌کند و تمیزها را
همان لحظه که پیدا شدند چاپ می‌کند و وقتی به تعداد کافی رسید می‌ایستد (`-need`، پیش‌فرض ۱۰):

```
xhttp-splitter scan -sni cloudflare.com -range 104.16.0.0/13 -range 172.64.0.0/13
```

## مخفی‌کردن SNI (ECH)

با Encrypted Client Hello، SNI واقعی داخل ClientHello رمز می‌شود؛ DPI فقط public name موجود
در config را می‌بیند.

```
xhttp-splitter -sni cloudflare.com -ips 104.16.0.0/13 -ech auto
```

`-ech` این‌ها را می‌پذیرد: `auto` (رکورد HTTPS DNS دامنه از 1.1.1.1 — پیشنهادی)،
`dns:HOST:PORT`، یک URL http(s)، یا base64 ECHConfigList. اگر edge ای‌سی‌اچ را رد کند
fail-closed می‌شود، پس اگر تونل با `-ech` کار کرد یعنی ECH واقعاً فعال است. تست روی endpoint
ECH Cloudflare که سپس `sni=encrypted` گزارش می‌دهد:

```
xhttp-splitter -sni crypto.cloudflare.com -ips 162.159.135.79,162.159.136.79 -ech auto
```

هر شبکه‌ای ECH را اجازه نمی‌دهد: بعضی DPIها هر ClientHello حاوی افزونهٔ ECH را blackhole
می‌کنند، حتی وقتی گرفتن config از DNS موفق است. ECH مستقل از تقسیم درخواست‌هاست، پس قبل از
تکیه بر آن حتماً روی لینک خودت تستش کن.

## Docker

```
docker build -t xhttp-splitter .
docker run --rm -p 10443:10443 -e XHTTP_SNI=cloudflare.com -e XHTTP_IPS=104.16.0.0/13 xhttp-splitter
```

ایمیجِ `scratch` حدود ۶ مگابایت، داخل کانتینر روی `0.0.0.0:10443` listen می‌کند.

## چطور کار می‌کند

- **هر درخواست یک اتصال** — هر POST/GET یک اتصال TLS تازه می‌گیرد که بلافاصله بسته می‌شود.
- **warm pool** — اتصال‌ها از پیش برقرار و با نرخ درخواست تنظیم می‌شوند؛ اتصال مرده هرگز تحویل داده نمی‌شود.
- **پنجرهٔ مرتب** — فقط یک پنجرهٔ کوچک از شماره‌های ترتیب در پرواز است و تحویل دنبال می‌شود تا بافر سرور سرریز نکند.
- **hedge و جایگزینی** — درخواستی که edge می‌پذیرد ولی جواب نمی‌دهد جای دیگر دوباره فرستاده و اتصال گیرکرده رها می‌شود.
- **probe، امتیازدهی و تازه‌سازی** — IPها زنده امتیاز می‌گیرند و استخر با سوختنشان دوباره از رنج‌ها probe می‌شود.
